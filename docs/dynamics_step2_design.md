## 1. 액추에이터 종류 — `motor` (직접 토크)

```xml
<actuator>
  <motor joint="torso_j1" forcerange="-700 700" ctrlrange="-700 700"/>
  ...  <!-- 17개 -->
</actuator>
```

### 왜 `position`이 아닌가

MuJoCo의 `position` 액추에이터는 PD를 내부에서 암시적으로 풀어 수치적으로 더
안정적입니다. 그런데 **중력 보상 피드포워드를 넣을 자리가 없습니다.** 중력을
`body_gravcomp`로 처리하면 중력 토크가 `actuator_force`에서 사라져서, 사용자가
요구한 **"관절별 토크 포화 시간"** 지표가 무의미해집니다. 실제 모터는 중력도
자기 토크로 버팁니다.

`motor` + 명시적 피드포워드를 쓰면 중력·관성·원심력이 전부 `d.actuator_force`에
집계되고 `forcerange`에 걸립니다. 포화 지표가 물리적 의미를 갖습니다.

안정성은 아래 2절의 damping 분리로 확보합니다. 만약 그래도 발산하면
`position` + 별도 중력 토크 집계로 후퇴합니다 (대안 설계, 5절).

### 베이스 처리

2단계에서 베이스는 아직 운동학입니다. 다만 `qpos`를 직접 쓰면 팔이 선회의
원심력·코리올리를 못 느낍니다. 그래서 `base_yaw`에만 **게인이 매우 큰 `position`
액추에이터**를 붙이고 `forcerange`는 걸지 않습니다. 명시적으로 **이상화된 구속**이며
4단계에서 실제 구동·조향 모터로 교체됩니다. 설정 파일에 `idealised: true`로 표시합니다.

## 2. 제어기 구조

```
tau_i = qfrc_bias_i                    # 역동역학 피드포워드 (중력 + 코리올리)
      + kp_i · (q_des_i − q_i)         # 명시적 비례항
      + kv_i · v_des_i                 # 속도 피드포워드
                                       # −kv_i·v_i 는 관절 damping이 암시적으로 담당
```

### damping 분리가 핵심

`kv·(v_des − v)`를 통째로 명시적으로 넣으면 큰 `kv`(최대 1173)에서 불안정해집니다.
대신 **`−kv·v` 부분을 관절 `damping`으로** 넘깁니다. `integrator="implicitfast"`가
damping을 암시적으로 적분하므로 이 항은 **무조건 안정**입니다. 남은 `+kv·v_des`만
피드포워드로 넣으면 수학적으로 동등합니다.

```xml
<joint name="torso_j1" ... damping="1173.29" armature="1.4666"/>
```

### 게인

목표 폐루프 2차 응답: **ωn = 20 rad/s (3.2 Hz), ζ = 1 (임계감쇠)**

```
kp_i = M_ii · ωn²        kv_i = 2 · ζ · M_ii · ωn
```

| 관절 | kp | kv (= damping) |
|---|---|---|
| torso_j1 | 11732.9 | 1173.29 |
| torso_j2 | 4375.1 | 437.51 |
| torso_j3 | 2217.1 | 221.71 |
| L/R_arm_j1 | 493.9 / 492.6 | 49.39 / 49.26 |
| L/R_arm_j2 | 349.6 / 347.7 | 34.96 / 34.77 |
| L/R_arm_j3 | 106.6 / 105.5 | 10.66 / 10.55 |
| L/R_arm_j4 | 133.2 / 132.0 | 13.32 / 13.20 |
| L/R_arm_j5 | 5.76 | 0.576 |
| L/R_arm_j6 | 15.40 / 15.36 | 1.540 / 1.536 |
| L/R_arm_j7 | 5.34 / 5.32 | 0.534 / 0.532 |

ωn = 20 rad/s 근거: 현재 궤적의 최대 관절 속도 사용률이 0.866이고 URDF velocity
한계가 0.9~2.7 rad/s이므로, 지령 궤적의 대역폭은 1 Hz 미만입니다. 3.2 Hz는 그보다
3배 이상 빠르므로 추종 지연이 지배적이지 않습니다. **이 값은 추정값**이며 설정 파일에
`source: estimated`로 들어가고, 2단계 검증에서 ωn ∈ {10, 20, 40}을 비교합니다.

**M_ii는 자세 의존적입니다.** 위 값은 운반 자세 한 점에서 측정했습니다. 2단계에서는
이 고정 게인을 쓰고, 사이클 전체에서 M_ii가 얼마나 변하는지 함께 기록합니다.
변동이 크면 3단계 전에 온라인 재계산으로 바꿉니다.

## 3. timestep — 5 ms → **2 ms** (동역학 모드만)

| | 5 ms | **2 ms** | 1 ms |
|---|---|---|---|
| `kp·dt²` (torso_j1) | 0.293 | **0.047** | 0.012 |
| M_ii 대비 | 1.0% | **0.16%** | 0.04% |
| 32개 실행 벽시계 (추정) | 488 s | **~1,200 s** | ~2,400 s |

2 ms면 가장 뻣뻣한 관절에서도 필요 armature가 M_ii의 0.16%라 물리적 왜곡이
무시할 수준입니다. 3·4단계에서 접촉이 들어오면 1 ms 재검토가 필요할 수 있습니다.

**운동학 모드는 5 ms를 유지합니다.** `reports/baseline_kinematic/`의 동결 결과를
그대로 재현해야 하기 때문입니다. timestep은 모드별 설정값입니다.

## 4. armature 추정 근거 — **데이터 없음, 추정값**

감속비·로터 관성 자료를 확보하지 못했습니다. 따라서 armature는 물리값이 아니라
**명시적 추정값**으로 다룹니다.

두 가지 하한이 있습니다:

1. **수치 안정성**: 명시적 비례항이 안정하려면 `armature ≳ kp·dt²`. 2 ms에서
   최대 0.047 (torso_j1).
2. **물리적 타당성**: 감속기를 쓰는 로봇 관절의 반사 로터 관성은 통상 링크 관성과
   같은 자릿수이거나 그 수 %입니다. **이 비율의 출처는 확인하지 못했습니다.**

채택안:

```
armature_i = max( β · M_ii ,  2 · kp_i · dt² ,  1e-4 )      β = 0.05  (추정)
```

| 관절 | β·M_ii | 2·kp·dt² | **armature** |
|---|---|---|---|
| torso_j1 | 1.4666 | 0.0939 | **1.4666** |
| torso_j3 | 0.2771 | 0.0177 | **0.2771** |
| L_arm_j1 | 0.0617 | 0.0040 | **0.0617** |
| L_arm_j7 | 0.00067 | 0.00004 | **0.00067** |

β = 0.05에 실측 근거는 없습니다. 이 값이 결론을 좌우하지 않음을 보이기 위해
**β ∈ {0.025, 0.05, 0.10} 민감도 시험을 통과 기준에 포함**합니다. 감속기 사양을
확보하면 설정 파일의 한 줄만 바꾸면 됩니다.

`dof_frictionloss`는 2단계에서 **0으로 둡니다** — 무부하 전류 자료가 없어
추정조차 근거가 없습니다. 4단계에서 현장 실측과 대조할 때 함께 도입합니다.

## 7. 설정 파일 구조

## 9. 구현 결과 — 설계안에서 바뀐 것

ωn=20, β=0.05, 검증 8토트, 접촉 임계값 측정 후 확정으로 승인받아 구현했습니다.
구현 파일은 `poc_sim/drive.py`(구동 분리), `poc_sim/config.py`·`config/dynamics.json`
(설정), `run.py --mode kinematic|dynamic`, 검증은 `scripts/verify_dynamics.py`입니다.

### 9.1 damping 분리는 역효과였습니다 — 되돌림

2절은 `−kv·v`를 관절 damping으로 넘기라고 했습니다. 근거는 "kv 최대 1173에서
명시적 적용은 불안정하다"였습니다. **측정해보니 사실이 아닙니다.** dt = 2 ms에서
`kv·dt`는 안정 한계 `2(M + armature)`의 **3.8%**입니다 — 모든 관절에서 동일하며
(kv와 armature가 둘 다 M_ii에 비례하므로 비율이 `ζ·ωn·dt/(1+β)`로 상수), 여유가
26배입니다.

게다가 분리가 **적극적으로 해롭습니다.** `kv·v_des`가 액추에이터를 통과하므로
`forcerange`를 먹어버립니다 — `torso_j2`가 물리적으로 상쇄될 항 때문에 380 N·m
한계에서 포화했습니다. 요구하신 "관절별 토크 포화 시간" 지표가 바로 무의미해지는
조건입니다. 전체 PD를 명시적으로 돌리면 `actuator_force`가 실제 모터 토크가 되고
포화는 0.7% → 0%로 사라집니다.

`config/dynamics.json`의 `control.explicit_damping`으로 되돌릴 수 있게 남겼습니다.

### 9.2 적재물 하중이 피드포워드에 아예 없었습니다

토트는 weld로 매달린 자유 바디여서 **운동학 트리에 없습니다.** 따라서 그 무게는
`qfrc_bias`에 들어오지 않고 제약력으로만 전달됩니다. 설계안의
`tau = qfrc_bias + kp·e + kv·v_des`만으로는 적재물이 통째로 빠집니다.

| 피드포워드 | 정지 처짐 |
|---|---|
| 설계안 그대로 | **45.2 mm** |
| 적재물 보상 추가 | **1.3 mm** |
| 적재물 보상 + 9.3의 게인 수정 | **0.252 mm** |

`mj_jacBodyCom`으로 토트 바디의 자코비안을 쓰면 효과가 **정확히 0**입니다 — 트리를
따라가므로 팔 dof 열이 전부 0입니다. 하중 경로는 weld이므로 **손 바디에 대한 토트
무게중심의 자코비안**을 써야 합니다(`mj_jac(point=토트 COM, body=tool)`). 양손이
균등 분담하고 불균형은 피드백항이 맡습니다.

### 9.3 게인 산정 관성이 틀렸습니다

2절의 `kp = M_ii·ωn²`에서 M_ii를 `mj_fullM`으로 재면 같은 이유로 적재물이 빠집니다.
손목에서 이 차이가 결정적입니다:

| 관절 | 링크만 M_ii | 적재물 반영 | 배수 |
|---|---|---|---|
| `torso_j1` | 29.83 | 31.50 | 1.1x |
| `L_arm_j4` | 0.338 | 0.662 | 2.0x |
| `L_arm_j6` | 0.040 | 0.204 | **5.1x** |
| `L_arm_j7` | 0.013 | 0.166 | **12.4x** |
| `L_arm_j5` | 0.013 | 0.280 | **22.0x** |

링크 관성만으로 게인을 잡으면 손목이 토트를 버틸 만큼의 토크를 **20배 낮은 강성**으로
내야 하므로, `L_arm_j5`가 350 mrad(20°) 뒤처집니다. 적재물 반영 관성으로 산정하니
최대 관절 오차가 **350 → 19.7 mrad**로 떨어집니다.

게인은 설계안대로 사이클 내내 **고정**이며, 적재 상태(최악)를 기준으로 잡습니다.
빈 상태에서는 과감쇠가 되는데 추종에는 손해가 없습니다.

### 9.4 통과 기준 측정 결과 (8토트, ωn=20, β=0.05)

| # | 항목 | 측정 | 판정 |
|---|---|---|---|
| 1 | 정지 처짐 | **0.252 mm** | PASS (<2 mm) |
| 2 | 손 추종 최대 | **40.5 mm** (rms 4.91 mm) | **FAIL** (<5 mm) |
| 3 | 관절 추종 | 최대 60.2 / rms 3.46 mrad | 기록 |
| 4 | 토크 포화 | **0.0000%**, 최대 사용 `torso_j2` 73.5% | PASS |
| 5 | 모드 일치 | 적재 슬롯·층 완전 일치 | PASS |
| 6 | 운동학 회귀 | qpos·토트 위치·이벤트 **바이트 동일** | PASS |
| 7 | β 민감도 | 아래 | **결론 불변 아님** |
| 8 | ωn 민감도 | 아래 | **결론 불변 아님** |
| 9 | 정상 관통 | 2.838 mm → 임계값 9 mm 확정 | 완료 |

9번은 우려가 빗나갔습니다. 동역학 정상 관통 최대가 **2.838 mm로 운동학 임계값 3 mm
아래**입니다. 그래도 자세·접촉 수에 따라 변하므로 3배 여유를 둬 9 mm로 잡았고,
`AVOID_REQUIRE` 14 mm보다 작으므로 실제 충돌은 여전히 잡힙니다.

### 9.5 민감도 — 두 추정값 모두 "결론 불변"이 성립하지 않습니다

4절은 β를 "결론을 좌우하지 않음을 민감도로 보이겠다"고 했습니다. **보이지 못했습니다.**

| β | 손 추종 최대 | 토크 포화 | 드리프트 |
|---|---|---|---|
| 0.025 | 94.3 mm | **57.3%** | 6.08 mm |
| **0.05** | 40.5 mm | 0.000% | 2.45 mm |
| 0.10 | 41.2 mm | 0.000% | 2.47 mm |

β = 0.025에서는 전 스텝의 57%가 토크 포화입니다. 0.05와 0.10은 사실상 같습니다.
즉 **β = 0.05는 안정 영역의 경계 바로 위**이고, armature는 물리적 로터 관성을
대표하는 값이 아니라 수치 안정화 역할을 하고 있습니다. 감속기 사양을 확보하면
실제 값이 0.05보다 작을 경우 **timestep을 함께 줄여야** 합니다.

| ωn | 결과 |
|---|---|
| 10 | 카메라 배치 검증 실패 |
| **20** | 통과, 손 최대 40.5 mm |
| 40 | 스택 드리프트 **106 mm** |
| 60 | 드리프트 105 mm |
| 60 초과 | 더 악화 |

게인을 올리면 추종이 좋아지는 대신 **적층이 무너집니다.** ωn = 20이 유일하게
완주하므로 승인된 값이 측정으로도 최선입니다. 다만 "결론 불변"은 아닙니다 —
양쪽으로 한 칸만 움직여도 실패합니다.

### 9.6 기준 2가 막힌 이유 — 게인 문제가 아닙니다

최대 오차 지점을 분해하면 `L_arm_j3` 40 mrad, `L_arm_j2` −22.8, `L_arm_j5` −34이고
토크는 8.7 / −11.1 / −2.9 N·m로 한계(80/150/25)에서 멉니다. 즉 포화가 아니라
`오차 = τ/kp`인 비례항 droop 그 자체입니다. 그런데 9.5가 보여주듯 kp는 올릴 수
없습니다.

올릴 수 없는 이유가 **양손 weld 과구속**입니다. 정지 처짐이 토트 무게를 없애도
동일하게 나옵니다(1.344 mm → 1.344 mm, 게인 수정 전 기준). 하중이 아니라 두 weld의
기하 불일치이고, 그 내부 힘이 kp에 비례해 커져 적재물을 흔듭니다.

남은 40.5 mm는 **후크 삽입 구간 한 곳**에서 20 ms에 걸쳐 쌓이는 단발 편차입니다
(2토트와 8토트에서 40.537 mm로 동일 — 같은 동작). 궤적이 구간별 선형(C0)이라 구간
경계에서 `v_des`가 계단으로 뛰는 것도 겹칩니다. 속도 피드포워드를 1차 저역통과
(τ = 1/ωn)로 보내 포화는 없앴지만 추종 오차는 그만큼 늘었습니다.

세 가지 선택이 남고, 전부 2단계 범위를 벗어납니다:

1. **잡기 모델** — 양손 weld 과구속 해소. 가장 근본적이고 3단계 사안입니다.
2. **궤적 평활화** — `track()`의 선형 보간을 S-curve로. 운동학 모드의 qpos 스트림이
   바뀌어 **기준선 재현(기준 6)이 깨집니다.**
3. **기준 2 재정의** — rms 4.91 mm는 기준 안이고 최대값은 후크 삽입 한 구간입니다.
   그 구간의 실제 여유(손잡이 구멍 40x116 mm vs 돌기 20x84 mm)로 다시 씁니다.

## 10. 축소된 범위 (2026-10-21 확정)

9절의 민감도 결과를 보고 사용자가 범위를 줄였습니다.

### 목표와 중단 조건

2단계의 목표는 **"토트를 든 채 안정적으로 궤적을 추종한다"** 하나입니다. 기한은
**2~3일**이고, 그 안에 안 되면 2단계를 **중단하고 운동학 + 역동역학(`mj_inverse`)
토크 검사로 전환**합니다. 즉 토크 한계·포화 질문은 동역학 적분 없이 운동학 궤적에
역동역학을 걸어 답하고, 동역학 추종은 포기합니다.

이 대안이 성립하는 근거는 9절에서 이미 나왔습니다 — 토크 여유가 최대 73.5%로 넉넉하고
포화가 0%이므로, 토크 질문의 답은 추종 품질과 무관하게 얻을 수 있습니다.

### 빠진 것

| 항목 | 처리 |
|---|---|
| β 민감도 스윕 (기준 7) | **하지 않음.** β = 0.05 고정 |
| ωn 민감도 스윕 (기준 8) | **하지 않음.** ωn = 20 고정 |
| armature | 관절당 **0.1 kg·m² 절대값으로 1회만** 비교해 토크 포화 결론이 바뀌는지 확인 |
| 고층(15층) 검증 시나리오 | 환경 치수 확정 후로 연기 |

`config/dynamics.json`의 `control.armature_absolute`가 그 1회 비교용입니다. null이면
`max(β·M_ii, 2·kp·dt², floor)` 규칙을 씁니다.

### 동역학 충돌 판정 — 관통 깊이에서 접촉 발생으로

깊이 임계값(9절에서 9 mm로 잡은 것) 대신 **"로봇이 들고 있지 않은 토트에 접촉했는가"**
로 판정합니다. 깊이는 솔버 파라미터에 따라 변하는 양이고, 실제로 알고 싶은 것은
"의도하지 않은 토트를 건드렸는가"이기 때문입니다.

정당한 접촉이 먼저 식별돼야 합니다 — 후크 삽입·안착(`engage()`는 돌기와 손잡이
턱의 접촉을 **요구**합니다)과 내려놓은 뒤 후크를 빼는 구간이 그렇습니다. 그래서
허용 집합은 이미 유지되고 있는 `ik.ignore_bodies`(들고 있는 토트 + 집는 중인 토트)를
씁니다.

**임계값은 0스텝으로 확정했습니다.** 8토트 정상 실행(347 s, 약 17만 스텝)에서 모든
로봇↔토트 접촉을 분류한 결과 허용 집합 밖 접촉이 **0건**이었습니다. 관찰된 것은
돌기↔손잡이 턱(안착, 각 1,200여 스텝), 돌기↔림(삽입·인출 시 스침, 각 70여 스텝),
그리고 운반 중인 토트뿐입니다.

판정은 MuJoCo 자체의 포함 판정(`dist < includemargin`)을 씁니다. `L_prong`의
margin 4 mm가 그 쌍의 `includemargin`이므로 **4 mm 안에 들어온 후크는 솔버가 실제
접촉으로 처리합니다** — `engage()`가 "턱을 눌러 박지 않아도 접촉으로 인정"하는 것이
이 구조입니다. 따라서 3 mm 떨어진 접촉도 근접이 아니라 접촉입니다.

### armature 1회 비교 결과 — 결론이 바뀝니다

관절당 **0.1 kg·m² 평탄**으로 바꾼 1회 비교입니다(8토트). 토크 포화 결론이
**완전히 뒤집힙니다.**

| | `max(β·M_ii, 2·kp·dt², floor)` | **0.1 평탄** |
|---|---|---|
| 토크 포화 | **0.0000%** | **17.56%** of steps |
| `torso_j1` | 65.7% 사용 | **700/700 N·m, 14.6% 포화** |
| `torso_j2` | 73.5% | **380/380, 17.6% 포화** |
| `torso_j3` | 38.1% | **380/380, 6.0% 포화** |
| 팔 14관절 | 포화 0% | **포화 0%** (영향 없음) |
| 적재 중 추종 rms | 3.85 mm | **55.65 mm** |
| 들고 있지 않은 토트 접촉 | 0 | **2,760 스텝** |
| 완주 | PASS | 카메라 배치 검증 실패 |

**몸통 3관절만 깨집니다.** 0.1 평탄은 `torso_j1`에 293배 감소(1.467 → 0.1),
`arm_j7`에 150배 증가(0.00067 → 0.1)입니다. `torso_j1`의 수치 안정 하한
`2·kp·dt²`가 **0.0999**이므로 0.1은 그 경계에 정확히 걸치고 여유가 0입니다.
몸통 제어기가 발산해 토크 한계를 때리고, armature가 늘어난 팔은 멀쩡합니다.

따라서 armature 규칙은 부수적 디테일이 아니라 **결론을 지탱하는 항목**입니다.
감속기 사양을 확보해 실제 값이 몸통에서 1.47 kg·m²보다 작게 나오면
**timestep을 함께 줄여야** 합니다. 이는 9.5절의 β 민감도 결과(0.025에서 57% 포화)와
같은 현상입니다.

### 검증 정밀도

**사이클 타임 0.1 s, 위치 1 mm** 수준이면 충분합니다. 이보다 작은 차이는 추적하지
않습니다 — 9절까지 문제가 됐던 13번째 자리 IK 차이나 40 ms 이벤트 시점 차이는
이 해상도 아래이므로 더 이상 회귀로 보지 않습니다. 토트 최종 좌표의 13 mm 차이는
이 해상도 위이지만, `reports/baseline_kinematic/README.md`에 적은 대로 혼돈적 정착
때문이므로 비교 지표가 아닙니다.
